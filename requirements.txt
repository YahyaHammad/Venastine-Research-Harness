# ROADMAP_v2 §16 TUI. EXACT, and this comment is textual's OWN record
# rather than a line borrowed from D22's, which is about `mcp`. The
# `>=1.0,<2.0` it replaces was written BEFORE 2.0 existed -- 1.0.0 shipped
# 2024-12-12 and 2.0.0 on 2025-02-16 -- so it was a
# don't-migrate-me-by-accident ceiling and never a judgement about 2.x.
# Nothing in the repo had evaluated 2.x, and the ceiling then sat there
# for twenty months while upstream reached 8.2.8.
#
# Exact for the reason batch 32 made `mcp` exact: an upper bound stops a
# MAJOR and lets a MINOR change behaviour underneath CI, which makes CI's
# result depend on when it ran.
#
# Moving it again is a deliberate step. Each of these was verified in hand
# against the installed package rather than read from a changelog, and
# each is what to re-measure next time:
#   * `Static.renderable` is `.content` since 6.0.0 (`.visual` is the
#     rendered form). 43 sites across 8 test files read it.
#   * `Static.update` sends a Rich `Text` through `visualize()`, which
#     converts it with `console=widget.app.console` -- so updating an
#     UNMOUNTED widget raises NoActiveAppError, and the suite builds these
#     panels bare everywhere. `tui.widgets.as_content` is the answer.
#     The conversion also drops `no_wrap` / `overflow`, silently; those
#     are `text-wrap` / `text-overflow` in app.tcss now.
#   * Textual markup replaced Rich markup at 2.0.0, and `markup=False` IS
#     honoured now -- on 1.0.0 it was stored and never read, which is what
#     tui/screens.py's `Text(...)` rule was written against (RA1).
#   * `textual-ansi` is GONE. `ansi-dark` / `ansi-light` replaced it at
#     8.2.5, `Theme` grew an `ansi: bool`, and the built-in roster is 21
#     rather than 12 -- so SELECTABLE_THEMES in tests/test_themes.py, and
#     every documented test count, moves with the pin.
#   * `dim` is resolved into the drawn COLOUR now instead of reaching the
#     cell as an attribute, which is what a test reading a drawn style
#     off the compositor sees.
#   * The kitty keyboard protocol reaches the WINDOWS driver since 6.6.0.
#     Batch 54's `shift+enter` note was written against its absence.
# Then re-run the TUI pilots dependabot.yml names -- ~410 run_test sites.

# ROADMAP_v2 §17 MCP client. Upper-bounded per D22 -- and D22 exists
# BECAUSE of this package: it was mid-major-version transition when §17
# was written, and 2.0.0 landed 2026-07-28 before implementation started.
#
# v2 is a real break for consumers, verified in hand rather than from the
# docs: result fields are snake_case (.content/.structured_content/
# .is_error, was camelCase), timeouts are float seconds (was timedelta),
# the exception is MCPError (was McpError), streamablehttp_client is
# removed, and httpx/httpx-sse are replaced by httpx2 -- which is why
# there are now two HTTP stacks installed. httpx stays; anthropic, openai
# and ddgs all still need it.
# EXACT, not the `>=2.0,<3` range this used to carry (batch 32, CI run
# 32778904550). D22's upper bound did its job -- no major migration -- but a
# MINOR still changed observable behaviour underneath it: 2.1.0 stopped
# passing a crashed tool's exception text back to the client ("the
# exception's own text stays on the server"), so a test asserting the
# message went red on main while every local run stayed green. The range
# meant CI's result depended on WHEN it ran, and CI was not testing what
# anyone runs locally -- which is the more serious half of that.
#
# So this is pinned the way anthropic, openai and google-genai already are.
# Moving it is now a deliberate step: read 2.1.0's split first -- a tool
# raising ToolError on purpose keeps its message, a tool that CRASHES has
# its text withheld -- and re-run tests/test_mcp_client.py, which is written
# to hold on both versions.
mcp==2.0.0
