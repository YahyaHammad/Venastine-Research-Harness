# ROADMAP_v2 §17 MCP client. Upper-bounded per D22 -- and D22 exists
# BECAUSE of this package: it was mid-major-version transition when §17
# was written, and 2.0.0 landed 2026-07-28 before implementation started.
#
# v2 is a real break for consumers, verified in hand rather than from the
# docs: result fields are snake_case (.content/.structured_content/
# .is_error, was camelCase), timeouts are float seconds (was timedelta),
# the exception is MCPError (was McpError), streamablehttp_client is
# removed, and httpx/httpx-sse are replaced by httpx2 -- which is why
# there are now two HTTP stacks installed. httpx stays: the harness imports
# it itself (fetch_url, arxiv, scholar, /connect, the hosted sign-in) and
# google-genai needs it. Since batch 234 anthropic and openai are on httpx2
# too, and ddgs needs neither (measured with `pip show` in a fresh venv).
# EXACT, not the `>=2.0,<3` range this used to carry (batch 32, CI run
# 32778904550). D22's upper bound did its job -- no major migration -- but a
# MINOR still changed observable behaviour underneath it: 2.1.0 stopped
# passing a crashed tool's exception text back to the client ("the
# exception's own text stays on the server"), so a test asserting the
# message went red on main while every local run stayed green. The range
# meant CI's result depended on WHEN it ran, and CI was not testing what
# anyone runs locally -- which is the more serious half of that.
#
# So this is pinned the way anthropic, openai and google-genai already are.
# Moving it is now a deliberate step: read 2.1.0's split first -- a tool
# raising ToolError on purpose keeps its message, a tool that CRASHES has
# its text withheld -- and re-run tests/test_mcp_client.py, which is written
# to hold on both versions.
#
# 2.2.0 SINCE BATCH 165's follow-up, for CVE-2026-59951: a Streamable HTTP
# SERVER kept every session's state with no expiry and no cap, so a client
# could grow its memory without bound. This harness is an MCP client and
# serves nothing, so it was never exposed -- the bump is because pip-audit
# fails on any advisory, and a fix existed. Taken the deliberate way, the
# split read first: 2.1.0 withholds a crashed tool's text and drops
# outputSchema/structuredContent for tools that return content blocks;
# 2.2.0 follows redirects only within the same origin (or http -> https on
# one host) and no longer honours a passed-in client's follow_redirects.
# Neither touches what this client does. test_mcp_client.py,
# test_mcp_config.py and the integration servers all pass on it, and
# mcp-types moves with it in lockstep.
#

# behaviour changes, against this client: httpx2 >=2.10.0 is required
# (it was 2.5.0); a 2025-11-25-or-earlier connection no longer sends an
# empty `_meta` or `params`, and `initialize` leaves `experimental` out,
