# Test dependencies. NOT part of the distribution (S18-07, batch 136).
#
# These four used to sit at the bottom of requirements.txt, and
# pyproject.toml reads that file for `[project].dependencies` via
# `dynamic`, so they were HARD REQUIREMENTS of the published package:
# `pip install venastine-research-harness` resolved pytest, pytest-mock,
# pytest-asyncio, pytest-xdist and execnet, and bin/venastine.mjs
# installed the same set into every end user's venv. Somebody who
# installed a research harness got a test runner and its scheduler.
#
# Read from TWO places on purpose, and they cannot drift: this file is
# what CI and a contributor install, and pyproject.toml's `test` extra
# names the same four so `pip install -e ".[test]"` works for anyone who
# never clones. `test_the_test_extra_matches_requirements_test` compares
# them -- #144's rule is that a hand-maintained duplicate is only as good
# as the gate over it, not that two copies are always wrong.
#
# The npm channel needs nothing: package.json's `files` allowlist names
# requirements.txt and not this file, so it never reaches a tarball.
# Previously absent, which the docs recorded as a known open item since
# §14: the suite has always needed pytest and pytest-mock, and §16's TUI
# pilot tests add pytest-asyncio. Listed now so `pip install -r` produces
# a working suite instead of one that fails at import.
pytest>=8.0
pytest-mock>=3.14
pytest-asyncio>=1.0
# Batch 109. NOT optional: pytest.ini's addopts carries `-n auto`, so
# without this `pytest` fails at argument parsing rather than merely
# running serially. That is deliberate -- a suite that silently takes
# eight times longer on a machine missing a package is worse than one
# that says which package.
#
# `>=` like its three siblings above rather than an exact pin. D22's
# argument for pinning is about packages whose behaviour CI's RESULT
# depends on; this one decides how the run is scheduled, and the three
# ordered sites that care are pinned by `--dist loadscope` in pytest.ini
# -- loadfile until batch 110 switched it, and this comment said loadfile
# for eighteen batches after that
# rather than by a version. Brings `execnet` (MIT), which is its only
# transitive.
pytest-xdist>=3.6
